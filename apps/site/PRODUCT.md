# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Individual developers using coding agents who want to see their token spend, cache savings and subscription value. Multi-machine and Tokenmaxx workflows are secondary.

## Product Purpose

A public marketing and documentation site for chaching. The primary action is running `npx chaching`; GitHub is secondary.

## Capabilities and Constraints

Use the shipping product as evidence. Runs locally. No chaching signup. No telemetry. Optional Cursor Admin API and PostgreSQL aggregate sync make network connections. Tokenmaxx integration reads local SQLite. Node >=24.16.0 is required. PolyForm Noncommercial, with commercial licensing through rai@rbutera.com. Do not describe it as open source.

## Brand Commitments

Preserve the existing gallows humour, Chaching! wordmark and Register & Receipt identity. Product receipt imagery keeps its fixed default palette and bundled fonts.

## Evidence on Hand

Approved content and imagery decisions are recorded in GitHub issues 21 and 22. README.md, CONFIG.md, docs/sync.md and CHANGELOG.md are content sources. Production dashboard and receipt renderers exist. Marketing assets must use fictional fixture data and actual production renderers.

## Product Principles

Show the actual product. Make installation immediate. Preserve personality and accurately describe optional connections. Keep documentation source-driven.
